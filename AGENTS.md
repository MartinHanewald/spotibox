## Project Overview

**spotibox** is a Spotify player designed for kids, running on a Raspberry Pi with physical GPIO button controls. It uses the Spotify Web API (via `spotipy`) to control playback on a named Spotify Connect device (`'SPOTIBOX'`), and responds to physical arcade buttons wired to the Pi's GPIO pins. Album art is displayed on an attached LCD screen via `pygame`.

- **Author:** Martin Hanewald
- **License:** MIT
- **Python:** ≥ 3.9
- **Version:** 0.2.0
- **Target hardware:** Raspberry Pi 3B+ with an audio HAT, 3.5" LCD HAT, and arcade buttons

## Architecture

### `spotibox/spotibox.py` — `Spotibox` class

The central class. Initialization and event loop are separated:

**`__init__()`** sets up state only (no blocking loop):
1. Loads album URIs via `_load_albums()` — tries `/mnt/albums/albums.py`, falls back to bundled `spotibox/albums.py`.
2. Initialises a fullscreen `pygame` display and shows a splash image (`spotibox.PNG` from `./assets/`).
3. Authenticates with Spotify via `SpotifyOAuth` (scopes: `user-read-playback-state`, `user-modify-playback-state`).
4. Discovers the Spotify Connect device named `'SPOTIBOX'` and stores its device ID. Raises `RuntimeError` with a clear message if the device is not found.
5. Polls `current_playback()` until a playback state is available.

**`run()`** enters the main event loop:
1. Calls `_setup_buttons()` to register all GPIO handlers (skipped when `debug=True`).
2. Registers SIGTERM/SIGINT handlers.
3. Runs the pygame event loop with idle-shutdown and LED-fade timers.

Key methods:

| Method | Purpose |
|---|---|
| `run()` | Main event loop — call after construction to start the player |
| `playback(uid)` | Start playback of a Spotify album, playlist, or artist URI |
| `pause_resume()` | Toggle pause/resume |
| `pause()` / `resume()` | Explicit pause / resume with position restore |
| `volume_up()` / `volume_down()` | Adjust volume ± `VOLUME_STEP` (10%), clamped to 0–100 |
| `next_track()` | Skip to next track |
| `refresh_current()` | Poll Spotify for current playback state; sets a safe mock dict if nothing is playing |
| `get_image(uid)` | Download album/playlist art to `./assets/` and return the filename |
| `display_image(filename)` | Render an image centred on the pygame screen |
| `display_track_number()` | OSD overlay showing current track number |
| `display_volume()` | OSD overlay showing current volume |
| `get_random_album(uid)` | For artist URIs: fetch all albums and return a random one |
| `_setup_buttons()` | Wire all GPIO pins to handler lambdas |
| `shutdown()` | Quit pygame and run `sudo shutdown -f now` via `subprocess.run` |
| `reset_timer()` | Reset the LED backlight timer and turn the LED on |

Module-level constants: `DEVICE_NAME`, `ALBUMS_PATH`, `ASSETS_DIR`, `VOLUME_STEP`, `IDLE_TIMEOUT`, `FADE_TIMEOUT`, `FPS`.

### `spotibox/cli.py` — Unified entry point

The Click CLI reads Spotify credentials from environment variables (`SPOTIPY_CLIENT_ID`, `SPOTIPY_CLIENT_SECRET`, `SPOTIPY_REDIRECT_URI`) with `--client-id`, `--client-secret`, `--redirect-uri` option overrides. Additional flags:

- `--debug` — skip GPIO setup (for development on non-Pi machines)
- `-v` / `--verbose` — enable DEBUG-level logging

Configures `logging.basicConfig()`, instantiates `Spotibox`, and calls `box.run()`.

Run via: `uv run spotibox [OPTIONS]`

### `spotibox/albums.py`

Hardcoded mapping of `album1`–`album8` to Spotify URIs. At runtime, the `_load_albums()` helper tries to load `/mnt/albums/albums.py` first (production mount point); if not found, falls back to the bundled `spotibox/albums.py` with a warning log. The file checked into the repo serves as a template / reference copy.

### `spotibox/multibutton.py` — `MultiButton` and `MultiButtonBoard`

A custom extension of `gpiozero.Button` and `gpiozero`'s composite device classes. `MultiButtonBoard` groups two GPIO buttons and routes to one of three callbacks depending on which combination is pressed:

- `pin1` only → `callbacks[0]`
- `pin2` only → `callbacks[1]`
- both pressed simultaneously → `callbacks[2]`

### `scripts/shutdown.py`

A standalone script (separate from the main app) that monitors GPIO pin 26. Holding the button for 3 seconds calls `sudo shutdown -f now`. Intended to run as a separate systemd service.

## GPIO Pin Mapping

| GPIO Pin (BCM) | Role |
|---|---|
| 23 | LED indicator |
| 4 | BUTTONPLAY1 → `albums.album1` |
| 27 | BUTTONPLAY2 → `albums.album2` |
| 22 | BUTTONPLAY3 → `albums.album3` |
| 5 | BUTTONPLAY4 (MultiButtonBoard 1 pin1) → `albums.album4` / `album7` |
| 6 | BUTTONPLAY5 (MultiButtonBoard 1 pin2) → `albums.album5` / `album7` |
| 13 | BUTTONPLAY6 (MultiButtonBoard 2 pin1) → `albums.album6` / `album8` |
| 26 | BUTTONPAUSE (MultiButtonBoard 2 pin2) → pause/resume / `album8` |
| 14 | BUTTONVOLUP → volume up |
| 15 | BUTTONVOLDOWN → volume down |
| 12 | BUTTONNEXT → next track |

Pins 19, 20, 21 are explicitly avoided (noted in comments).

## Configuration / Secrets

Spotify credentials are passed at runtime via environment variables or CLI options (not stored in files):
- `SPOTIPY_CLIENT_ID` / `--client-id`
- `SPOTIPY_CLIENT_SECRET` / `--client-secret`
- `SPOTIPY_REDIRECT_URI` / `--redirect-uri`

`SpotifyOAuth` will cache the token locally in `.cache`. Do not commit `.cache` files.

The Spotify Connect target device must be named exactly `'SPOTIBOX'` (configured via the `DEVICE_NAME` constant in `spotibox.py`).

### Raspotify Authentication

Raspotify (librespot) no longer supports password-based login. The headless OAuth flow is used instead:

1. `scripts/setup_audio.sh` installs Raspotify and configures `LIBRESPOT_SYSTEM_CACHE` + credential caching.
2. `scripts/setup_spotify_auth.sh` runs librespot's headless OAuth flow — it prints a URL to open in any browser, the user logs in, and pastes the redirect URL back. Credentials are cached in `/var/cache/raspotify/credentials.json`.
3. After auth, `LIBRESPOT_USERNAME` is set in `/etc/raspotify/conf` so Raspotify auto-authenticates on startup.

This ensures the SPOTIBOX device is visible to the Spotify account without needing another device to stream to it first.

## How to Run

```bash
# Install uv (if not already installed)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Install all dependencies
make install
# or: uv sync --group dev

# --- Raspberry Pi first-time setup ---
# 1. Install audio HAT driver + Raspotify
sudo bash scripts/setup_audio.sh
# 2. Authenticate Raspotify with your Spotify account (headless OAuth)
sudo bash scripts/setup_spotify_auth.sh

# Run on the Raspberry Pi (credentials via env vars)
export SPOTIPY_CLIENT_ID="your-id"
export SPOTIPY_CLIENT_SECRET="your-secret"
export SPOTIPY_REDIRECT_URI="https://example.com/callback/"
uv run spotibox

# Or pass credentials as options (will prompt if not provided)
uv run spotibox --client-id YOUR_ID --client-secret YOUR_SECRET --redirect-uri YOUR_URI

# Development mode (skip GPIO)
uv run spotibox --debug --verbose
```

## Key Conventions and Gotchas

1. **Albums loaded from `/mnt/albums/albums.py` at runtime.** If that file is missing, the bundled `spotibox/albums.py` is used as a fallback (with a warning log). Do not hardcode album URIs into `spotibox.py`.

2. **Asset files live in `./assets/`** (the `ASSETS_DIR` constant). The process must be launched from the project root, or paths will break. Album art is downloaded and cached there as `<id>.jpg`; a `temp.bmp` intermediate is used during display.

3. **`__init__()` vs `run()`:** The `Spotibox` constructor sets up state and authenticates but does **not** enter the event loop. Call `box.run()` to start the main loop. This separation enables testing without blocking.

4. **`refresh_current()` returns `None` silently on network errors** and leaves `self.current` in its previous state. Callers should handle this.

5. **Logging:** All output goes through Python's `logging` module (`logger = logging.getLogger(__name__)`). Use `--verbose` on the CLI for DEBUG-level output.

6. **`sandbox/`** contains exploratory scripts that are not part of the package. They may have missing imports or broken state.

7. **`shutdown()` uses `subprocess.run(['sudo', 'shutdown', ...])`** which requires the running user to have passwordless sudo for the `shutdown` command.
