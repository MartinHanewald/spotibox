## Project Overview

**spotibox** is a Spotify player designed for kids, running on a Raspberry Pi with physical GPIO button controls. It uses the Spotify Web API (via `spotipy`) to control playback on a named Spotify Connect device (`'SPOTIBOX'`), and responds to physical arcade buttons wired to the Pi's GPIO pins. Album art is displayed on an attached LCD screen via `pygame`.

- **Author:** Martin Hanewald  
- **License:** MIT  
- **Python:** ≥ 3.6  
- **Version:** 0.2.0  
- **Target hardware:** Raspberry Pi 3B+ with an audio HAT, 3.5" LCD HAT, and arcade buttons

## Architecture

### `spotibox/spotibox.py` — `Spotibox` class

The central class. On instantiation it:
1. Initialises a fullscreen `pygame` display and shows a splash image (`spotibox.PNG` from `./assets/`).
2. Authenticates with Spotify via `SpotifyOAuth` (scopes: `user-read-playback-state`, `user-modify-playback-state`).
3. Discovers the Spotify Connect device named `'SPOTIBOX'` and stores its device ID.
4. Polls `current_playback()` until a device is found.
5. Calls `buttonconfig()` to register all GPIO handlers (skipped when `debug=True`).

Key methods:

| Method | Purpose |
|---|---|
| `playback(uid)` | Start playback of a Spotify album, playlist, or artist URI |
| `pause_resume()` | Toggle pause/resume |
| `pause()` / `resume()` | Explicit pause / resume with position restore |
| `volume_up()` / `volume_down()` | Adjust volume ±10% |
| `next_track()` | Skip to next track |
| `refresh_current()` | Poll Spotify for current playback state; sets a safe mock dict if nothing is playing |
| `get_image(uid)` | Download album/playlist art to `./assets/` and return the filename |
| `display_image(filename)` | Render an image centred on the pygame screen |
| `display_track_number()` | OSD overlay showing current track number |
| `display_volume()` | OSD overlay showing current volume |
| `get_random_album(uid)` | For artist URIs: fetch all albums and return a random one |
| `buttonconfig()` | Wire all GPIO pins to handler lambdas |
| `shutdown()` | Quit pygame and run `sudo shutdown -f now` |
| `reset_timer()` | Reset the LED backlight timer and turn the LED on |
| `service_shutdown()` | SIGTERM/SIGINT handler for clean exit |

### `spotibox/albums.py`

Hardcoded mapping of `album1`–`album8` to Spotify URIs. At runtime this file is **not** imported from the package; instead `spotibox.py` loads it dynamically from `/mnt/albums/albums.py` using `importlib`:

```python
spec = importlib.util.spec_from_file_location("albums", "/mnt/albums/albums.py")
albums = importlib.util.module_from_spec(spec)
spec.loader.exec_module(albums)
```

This means the albums file is expected to live on a mounted volume at `/mnt/albums/albums.py` in production. The file checked into the repo (`spotibox/albums.py`) serves as a template / reference copy.

### `spotibox/multibutton.py` — `MultiButton` and `MultiButtonBoard`

A custom extension of `gpiozero.Button` and `gpiozero`'s composite device classes. `MultiButtonBoard` groups two GPIO buttons and routes to one of three callbacks depending on which combination is pressed:

- `pin1` only → `callbacks[0]`  
- `pin2` only → `callbacks[1]`  
- both pressed simultaneously → `callbacks[2]`

### `scripts/shutdown.py`

A standalone script (separate from the main app) that monitors GPIO pin 26. Holding the button for 3 seconds calls `sudo shutdown -f now`. Intended to run as a separate systemd service.

### `run.py`

The practical launch script. Prompts for `client_id`, `client_secret`, and `redirect_uri` via Click options, then instantiates `Spotibox`.

## GPIO Pin Mapping

| GPIO Pin (BCM) | Role |
|---|---|
| 23 | LED indicator |
| 4 | BUTTONPLAY1 → `albums.album1` |
| 27 | BUTTONPLAY2 → `albums.album2` |
| 22 | BUTTONPLAY3 → `albums.album3` |
| 5 | BUTTONPLAY4 (MultiButtonBoard 1 pin1) → `albums.album4` / `album7` |
| 6 | BUTTONPLAY5 (MultiButtonBoard 1 pin2) → `albums.album5` / `album7` |
| 13 | BUTTONPLAY6 (MultiButtonBoard 2 pin1) → `albums.album6` / `album8` |
| 26 | BUTTONPAUSE (MultiButtonBoard 2 pin2) → pause/resume / `album8` |
| 14 | BUTTONVOLUP → volume up |
| 15 | BUTTONVOLDOWN → volume down |
| 12 | BUTTONNEXT → next track |

Pins 19, 20, 21 are explicitly avoided (noted in comments).

## Configuration / Secrets

Spotify credentials are passed at runtime (not stored in files):
- `SPOTIPY_CLIENT_ID` / `--client_id`
- `SPOTIPY_CLIENT_SECRET` / `--client_secret`
- `SPOTIPY_REDIRECT_URI` / `--redirect_uri`

`SpotifyOAuth` will cache the token locally in `.cache`. Do not commit `.cache` files.

The Spotify Connect target device must be named exactly `'SPOTIBOX'` (see `spotibox.py` line that calls `next(d['id'] for d in devs['devices'] if d['name'] == target)`).

## Key Conventions and Gotchas

1. **Albums loaded from `/mnt/albums/albums.py` at runtime.** Do not hardcode album URIs into `spotibox.py` — they belong in the albums module. The in-repo `spotibox/albums.py` is a template only.

2. **Asset files live in `./assets/`** relative to the working directory. The process must be launched from the project root, or paths will break. Album art is downloaded and cached there as `<id>.jpg`; a `temp.bmp` intermediate is used during display.

3. **The `Spotibox` class is not safe to instantiate in unit tests** without mocking `pygame`, `gpiozero`, and `spotipy`. Use `debug=True` to skip GPIO setup, but display init still runs.

4. **`refresh_current()` returns `None` silently on network errors** and leaves `self.current` in its previous state. Callers should handle this.

5. **Volume clamping bug:** `volume_up` and `volume_down` both use `max(0, ...)` — `volume_up` should use `min(100, current_vol + 10)`.

6. **`cli.py` is a stub.** The actual launch script is `run.py`. The `spotibox` console entry point (from `setup.py`) points to `cli.py:main` which only prints placeholder text.

7. **`shutdown()` uses `os.system('sudo shutdown ...')`**, which requires the running user to have passwordless sudo for the `shutdown` command. The alternative `scripts/shutdown.py` uses `subprocess.check_call` which is safer.

8. **`spotibox_test.py` in the repo root** is a scratch/debug script containing hardcoded credentials and syntax errors. It is not part of the test suite. Do not execute or modify it as part of normal development.

9. **`sandbox/`** contains exploratory scripts that are not part of the package. They may have missing imports or broken state.
